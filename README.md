# ride_bot

Telegram-бот для одной группы друзей: участники предлагают маршруты/направления
поездок (предложение уходит на модерацию админу), админ группы запускает опрос
(вручную или по расписанию), а выбранное место исключается из будущих опросов,
пока админ не вернёт его вручную.

## Стек

- Node.js + TypeScript
- [grammY](https://grammy.dev/) — Telegram Bot API, long polling
- Firestore (через `firebase-admin`) — хранилище данных
- `node-cron` — расписание автосоздания опроса
- `luxon` — валидация дня недели / времени / IANA-таймзоны

## Команды

| Команда | Кто | Где | Что делает |
|---|---|---|---|
| `/suggest <текст>` | любой участник | группа | отправить вариант маршрута на рассмотрение админу |
| `/list` | любой участник | группа | список уже одобренных вариантов (📷 N — сколько фото в архиве места) |
| `/photo <номер>` | любой участник | группа | ответом на любое сообщение (фото, альбом, видео, текст) прикрепить его к месту; от не-админа — через модерацию |
| `/place <номер>` | любой участник | группа | карточка места: статус, даты поездок и ссылки на фото и сообщения из архива |
| `/history` | любой участник | группа | прошлые поездки, самые активные авторы идей, варианты, которые чаще всего проигрывали |
| `/unphoto` | админ | группа | ответом на фото или исходное сообщение убрать его из архива места |
| `/edit <номер> <текст>` | админ | группа/ЛС | изменить текст варианта |
| `/delete <номер>` | админ | группа/ЛС | удалить вариант навсегда (с подтверждением) |
| `/exclude <номер>` | админ | группа/ЛС | вручную исключить активный вариант из пула |
| `/create_poll` | админ | группа/ЛС | создать опрос сейчас |
| `/set_schedule <день> <ЧЧ:ММ> [таймзона]` | админ | группа/ЛС | настроить автосоздание опроса; без таймзоны — `DEFAULT_TIMEZONE` |
| `/set_close_schedule <день> <ЧЧ:ММ> [таймзона]` | админ | группа/ЛС | настроить автозакрытие опроса (например, `sunday 12:00`) |
| `/get_schedule` | админ | группа/ЛС | показать расписание создания и закрытия опроса |
| `/meet <ЧЧ:ММ> <точка>` | админ | группа/ЛС | точка и время старта субботней поездки (до 20:00 пятницы), публикуется в группе |
| `/close_poll` | админ | группа | закрыть опрос вручную и подтвердить, куда съездили |
| `/cancel_poll` | админ | группа | закрыть опрос без подсчёта результатов, место не исключается |
| `/restore <номер>` | админ | группа/ЛС | вернуть исключённый вариант в пул |
| `/excluded` | админ | группа/ЛС | список исключённых (использованных) вариантов |
| `/set_reminder_time <ЧЧ:ММ> [таймзона]` | админ | группа/ЛС | настроить время памятки про `/suggest` (приходит через день); без таймзоны — `DEFAULT_TIMEZONE` |
| `/set_reminder_text <текст>` | админ | группа/ЛС | заменить текст памятки на свой |
| `/get_reminder` | админ | группа/ЛС | показать текущее время и текст памятки |
| `/start` | любой | ЛС | зарегистрироваться на DM-уведомления (нужно админам) |
| `/help` | любой | группа/ЛС | список команд — для админа показывает ещё и админский раздел |

Админский статус проверяется live через Telegram (`getChatMember`) — это
реальные админы/создатель группы, не отдельный список.

## Модерация предложений

`/suggest` не добавляет вариант сразу в список — он попадает в очередь
(`status: "pending"`) и появляется в `/list`/опросах только после того, как
кто-то из админов одобрит его. Одобрение/отклонение — кнопками **Одобрить** /
**Отклонить** прямо в DM-уведомлении о новом предложении (отдельной команды
для этого нет). Если ни один админ не зарегистрирован на DM-уведомления
(см. ниже про `/start`) — предложение так и останется висеть в очереди, кнопки
показать будет некому.

Отклонённое предложение помечается `status: "rejected"` и хранится (не
удаляется) — повторно предложить тот же текст нельзя, `/suggest` сразу
откажет со ссылкой на то, что вариант уже отклонён. Команды для отмены
отклонения сейчас нет.

## Фотоархив поездок

После поездки фото из группы можно привязать к месту, чтобы при планировании
следующих поездок было видно, где уже были и как там было.

- Ответьте на сообщение командой `/photo <номер>` (номер — из `/list`
  или `/excluded`, выигравшие места лежат там). Если фото из альбома, бот
  прикрепит весь альбом. Прикрепить можно и любое другое сообщение — видео,
  файл, текст с впечатлениями.
- `/place <номер>` не присылает сами фото, а даёт список ссылок на исходные
  сообщения в группе: одна строка на каждый `/photo` (альбом — одной ссылкой
  на первое фото), с датой, что там и кто добавил. Показываются последние 30.
- Фото от админа прикрепляются сразу. Фото от остальных уходят админам в ЛС
  (альбом + кнопки **Одобрить** / **Отклонить**, одно решение на всю пачку).
- Ссылки ведут на оригиналы: если сообщение удалить из группы, ссылка
  перестанет открываться. Админам на модерацию бот по-прежнему присылает
  сами фото и копии сообщений, чтобы было видно, что одобряют.
- Альбомы бот запоминает в памяти на 7 дней. Если бот перезапускался после
  того, как альбом отправили, прикрепится только фото, на которое ответили, —
  бот об этом скажет, и остальные фото можно прикрепить так же, ответами.
- `/unphoto` — ответом на исходное сообщение в группе.
- Одно и то же фото к одному месту дважды не прикрепится.
- `/delete` удаляет место вместе с его архивом.

## «В этот день»

Каждый день в 12:00 (по `DEFAULT_TIMEZONE`) бот проверяет, не годовщина ли
сегодня у какой-нибудь поездки, и если да — пишет в группу «N лет назад мы
ездили: …» со ссылками на фото и сообщения из архива этого места (до трёх,
остальное — в `/place`). Если архив пуст, бот предлагает прикрепить фото.

- Поездка — опрос с подтверждённым местом, дата — суббота поездки (см.
  «Недельный цикл»).
- Пост — не чаще раза в день, даже после перезапуска. Если бот был выключен в
  12:00, в этот день поста не будет.
- Поездки 29 февраля вспоминаются только в високосные годы.

## Ежедневная памятка

Если задать время через `/set_reminder_time`, бот раз в день будет присылать
в группу напоминание предложить вариант поездки (текст по умолчанию — см.
`DEFAULT_REMINDER_TEXT` в `src/constants.ts`). Пока время не задано —
напоминание не отправляется. Текст можно заменить своим через
`/set_reminder_text`, показывается он сразу с придуманным по умолчанию.

## Недельный цикл

| Когда | Что происходит |
|---|---|
| по `/set_schedule` (например, понедельник) | бот создаёт и закрепляет опрос |
| пн–пт | голосуем |
| пятница 18:00 | если точка старта ещё не указана — напоминание админам в ЛС |
| пятница до 20:00 | админ указывает старт: `/meet 09:00 <точка>` — бот публикует в группе |
| пятница 20:00 | если так и не указана — повторное напоминание админам |
| суббота | едем — это и есть дата поездки |
| по `/set_close_schedule` (например, воскресенье) | опрос закрывается сам, админам — кнопки «Съездили: …» / «Никуда не ездили» |
| после подтверждения | место исключается из пула, в группе — «Съездили в …» и просьба сохранить фото через `/photo` |

- Дата поездки — суббота перед подтверждением (если подтвердили в
  воскресенье — вчерашняя суббота). Она показывается в `/history`, `/place` и
  в постах «В этот день». Для поездок, подтверждённых до этой версии, берётся
  суббота перед закрытием опроса.
- Время напоминаний про старт (пятница 18:00 и 20:00) — по `DEFAULT_TIMEZONE`,
  зашито в коде.
- Если бот был выключен в момент автозакрытия, он закроет опрос при запуске
  (если опрос был создан до этого момента).

## Опрос

- Не анонимный (`is_anonymous: false`).
- Максимум **10 вариантов всего** (лимит Telegram): до 9 самых новых реальных предложений
  + обязательный вариант **«Мимокрокодил»**, который добавляется всегда последним.
  Если побеждает «Мимокрокодил» — в этот раз никуда не едем, ни одно предложение
  не исключается из пула.
- Если бот был выключен в момент, заданный `/set_schedule`, он создаст опрос
  при запуске — при условии, что с того момента прошло не больше 48 часов и
  опрос за это время не создавали. Расписание, заданное уже после пропущенного
  момента, догоном не срабатывает.

**Важно:** Telegram не позволяет боту первым написать пользователю в ЛС.
Чтобы админ получал уведомления о новых `/suggest`, он должен один раз
написать боту `/start` в личных сообщениях.

## Локальный запуск

1. Создать бота через [@BotFather](https://t.me/BotFather), получить `BOT_TOKEN`.
2. Добавить бота в тестовую группу и сделать админом.
3. Получить `GROUP_CHAT_ID` (например, залогировав `ctx.chat.id` из любого апдейта).
4. Создать проект Firestore, сгенерировать ключ сервисного аккаунта (JSON).
5. Скопировать `.env.example` → `.env` и заполнить все переменные
   (`FIREBASE_SERVICE_ACCOUNT_JSON` — весь JSON-ключ одной строкой).
6. Установить зависимости и запустить:

```bash
npm install
npm run dev
```

Проверки (не требуют `.env` и Firestore):

```bash
npm run typecheck   # tsc — код и тесты
npm run lint        # oxlint
npm test            # node:test — чистые функции и синхронность версий
```

Интеграционные тесты гоняют команды целиком (предложения, опросы, фотоархив)
на эмуляторе Firestore с поддельным Telegram API:

```bash
npm run test:integration
```

Нужна Java 11+ (эмулятор качается сам при первом запуске, `firebase-tools`
запускается через `npx` и в зависимости проекта не входит, чтобы не утяжелять
сборку аддона). Тесты лежат в `src/integration/*.itest.ts`, общий каркас —
`src/integration/harness.ts`.

CI (`.github/workflows/ci.yml`) на каждый push в `main` и на pull request
прогоняет проверку типов, линтер, обычные тесты, сборку и интеграционные тесты.

При каждом релизе версия поднимается и в `config.yaml`, и в `package.json`
(`npm version <x.y.z> --no-git-tag-version`) — тест проверяет, что они совпадают.

## Деплой

Бот работает через long polling — публичный URL/вебхук не нужен, только
долгоживущий процесс.

Основной вариант — **Raspberry Pi с Home Assistant OS**, бот ставится как
локальный HA-аддон (файлы `config.yaml`, `build.yaml`, `Dockerfile`, `run.sh`
в корне проекта). Подробная пошаговая инструкция — в [DEPLOY.md](./DEPLOY.md).

Для обычного Node-хостинга (VPS, Oracle Cloud Free Tier и т.п., без HAOS):

```bash
npm run build
npm start
```

`Procfile` объявляет процесс как `worker` (background worker, без HTTP-порта).
Если конкретный хостинг всё же требует привязку порта даже для worker-сервиса,
задайте `PORT` — поднимется минимальный healthcheck-сервер, не влияющий на
логику бота. Он отвечает 200, пока бот успешно получает обновления от Telegram,
и 503, если long polling остановился или завис дольше 90 секунд. Полный разбор вариантов (включая почему Render/Fly.io/Railway не
подходят бесплатно для always-on воркера в 2026 году) — в DEPLOY.md.

## Firestore-индексы

Пара запросов (`/list`, `/excluded`) фильтруют по `status` и одновременно
сортируют по другому полю (`addedAt`/`excludedAt`) — Firestore требует для
этого составной индекс. При первом реальном вызове такого запроса Admin SDK
вернёт ошибку `FAILED_PRECONDITION` с прямой ссылкой на консоль Firebase для
одного клика создания нужного индекса — это ожидаемо, просто перейдите по
ссылке один раз на проде. Запросы фотоархива составных индексов не требуют.

## Модель данных (Firestore)

- `suggestions/{id}` — предложения маршрутов (`seq`, `text`, статус pending/active/excluded/rejected)
- `polls/{id}` — опросы (открыт/закрыт, соответствие опций и предложений, победитель)
- `config/main` — единственный документ конфигурации (chat id группы, расписание)
- `adminRegistrations/{userId}` — кто из пользователей нажал `/start` в ЛС
- `counters/suggestionSeq` — счётчик для присвоения `seq`
- `placePhotos/{id}` — фото из поездок, привязанные к месту (`suggestionId`, `fileId`, `fileUniqueId`, `batchId`, статус pending/approved/rejected); у предложения есть счётчик `photoCount` одобренных фото
